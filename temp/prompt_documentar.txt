Actúa como Technical Writer senior, DevOps Engineer y desarrollador full-stack responsable de crear la documentación definitiva de este proyecto.

Trabaja exclusivamente sobre el código, configuración y documentación que ya existen en el workspace. No inventes funcionalidades, comandos, endpoints, variables de entorno, servicios ni requisitos que no estén realmente implementados.

## Objetivo

Genera documentación completa, clara y reproducible para que una persona técnica pueda:

1. Entender qué hace el proyecto.
2. Instalarlo desde cero en Linux, macOS o Windows con WSL2.
3. Configurarlo sin exponer secretos.
4. Ejecutarlo localmente con Docker.
5. Usar cada perfil del sistema.
6. Ejecutar tests, lint, build y pruebas E2E.
7. Diagnosticar errores comunes.
8. Instalarlo en otro equipo y restaurar datos de forma segura.
9. Prepararlo para staging o producción.

## Regla crítica

Documenta únicamente lo que esté implementado y sea verificable.

Si una fase, función, integración o comando está especificado pero no está implementado, indícalo claramente como:

- `Pendiente`
- `Parcialmente implementado`
- `No verificado`
- `Requiere configuración externa`

Nunca lo presentes como funcional.

No modifiques código de aplicación, migraciones, infraestructura, dependencias ni tests. Solo crea o actualiza archivos de documentación.

- Enlaces a toda la documentación en `docs/`.
- Comandos principales verificados.
- Aviso de que no deben utilizarse secretos reales ni credenciales de producción en local.

### `docs/README.md`

Debe actuar como índice navegable de toda la documentación.

## Validación final

Cuando termines:

1. Revisa todos los enlaces Markdown.
2. Asegura que todos los comandos están presentes en scripts/configuración reales.
3. Confirma que no hay secretos reales documentados.
4. Confirma que no se presentan funcionalidades pendientes como terminadas.
5. Genera:

```text
docs/GENERACION_DOCUMENTACION.md
```

Con:

- Archivos creados o modificados.
- Fuentes inspeccionadas.
- Funciones no documentadas por falta de implementación o evidencia.
- Comandos verificados y comandos no verificados.
- Preguntas o bloqueos pendientes.

Finalmente, muéstrame un resumen de los documentos generados y detente.
